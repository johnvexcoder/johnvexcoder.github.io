# Testing strategy — 1 November 2026

1. Preserve Git status and file hashes; retain existing source edits. Keep temporary logs/data out of source and production exports.
2. Use native project scripts for typecheck, lint, Node tests, static build, SEO and export validation in the implementation phase. Phase 0 only inspects the existing export and tooling fixtures; it does not rebuild production artifacts.
3. Use isolated Playwright contexts or the project CLI for routes, keyboard, viewport widths, focus, menu, history and forms. Session scope must stay in one shell process in this managed environment because detached browser daemons are cleaned up between executions. Set an allowed `XDG_CACHE_HOME` and choose an allowed output directory. Never attach to a personal browser profile.
4. Axe automated checks plus keyboard/focus/zoom/reduced-motion/manual review. Automated passes are not WCAG certification. Existing Next lint configuration is retained; a separate jsx-a11y package is not assumed installed.
5. Lighthouse CI collect uses explicit local URLs and numberOfRuns; do not upload results or add CI deployment steps in Phase 0. Use the same browser, serving/compression, device profile and throttling for comparative results. The fixture audit proves execution only; it is not a portfolio benchmark.
6. Existing check:export validates local resources/links; check:seo validates metadata/schema/sitemap. SEO-pro offline helpers independently parse selected HTML/XML. A bounded public HTTP sample tests reachability; transient failures stay distinct from broken-link findings.
7. Knip runs read-only with --include dependencies. Its current candidate is prettier, but the formatter is intentionally used during development; do not auto-remove it. Next's bundled `next analyze --help`/`next analyze --output` is the supported future Turbopack analyzer; do not add a Webpack analyzer to this build.
8. Contact tests use intercepted requests for success/validation/rate-limit/network cases. No submission during Phase 0. Live CAPTCHA and delivery checks in the later implementation phase must be clearly distinguished from mocks and may need user participation. Never solve CAPTCHA silently.
9. Check prod artifacts for route existence, meaningful no-JS content, canonical HTML, mirror links, source maps, public secrets and exact verification bytes before any later release.

Developer tool installation: `npm ci --prefix .codex/tools --ignore-scripts` restores the pinned isolated toolchain. Do not run this in the root application package. Binaries live in `.codex/tools/node_modules/.bin/`. Use `.codex/tools/playwright-cli.json` for normal local execution; under restricted paths, copy it to an allowed workspace and override outputDir. Do not commit node_modules or private reports.
